# AGENT_WORKFLOW.md — Mandatory workflow for any AI agent touching this repo

> This project is a **human-in-the-loop** swing trading bot with **frozen contracts**.
> Architecture decisions are made by the human. The AI never decides them.

The Control Center (`control_center/`) is the **single source of truth** for
what exists in this codebase, what is production, what is legacy, and what is
being migrated. Read it before changing anything.

---

## BEFORE modifying any code

Perform these steps **in order** and state the answers in your reply:

1. **Read `control_center/ARCHITECTURE.md`** — the human-readable map.
2. **Read `control_center/ARCHITECTURE.yaml`** — the machine-readable map.
3. **Query the Module Registry** — `modules` table (or the *Module Registry* page)
   for the target file(s): `type`, `status`, `canonical`, `production_used`,
   `research_used`, `replacement_module`, `evidence`.
4. **Check the Dependency Registry** — `dependencies` table:
   who imports the target, and what the target imports.
5. **Check the Migration Registry** — `migrations` table: is this module already
   mid-migration? Do not build on a component that is being replaced.
6. **Check the existing canonical implementation** — `canonical=1` for the
   subsystem. If a canonical implementation exists, extend it; do not add a
   parallel one.
7. **Identify production impact** — does the target have `production_used=1`?
   If yes, the change touches the frozen production path and needs a freeze
   decision.
8. **Only then modify code.**

Additionally, for this repo:

- Respect the freeze contracts:
  `regime_dual_engine/REGIME_V1_FREEZE.md` and `src/agents/SETUP_V1_FREEZE.md`.
  Any strategy idea goes to the matching `*_V2_BACKLOG.md`, **not** into code.
- One variable at a time (controlled experiments), or the change is not measurable.
- Do **not** delete any file. Deletion requests are answered by the registry's
  delete-safety panel and require an explicit human decision.

## AFTER modifying code

1. **Update the registry** — run `python control_center/refresh_registry.py`.
2. **Update dependencies** if imports changed (the refresh recomputes them).
3. **Update architecture** — `ARCHITECTURE.md` / `ARCHITECTURE.yaml` are
   regenerated by the refresh (do not hand-edit them).
4. **Record the migration/change** — add or update a row in `migrations`
   (or the *Migration Board*), with status, next action, blocker.
5. **Run the relevant tests** — e.g. `production/tests/*`,
   `regime_dual_engine/tests/test_regime_dual.py`.
6. **Report affected modules** — list every module whose status/behaviour changed.

---

## Ground rules (non-negotiable)

| Rule | Meaning |
|---|---|
| READ-ONLY first | Archaeology before action. Inventory, then change. |
| Never auto-delete | The registry never deletes; it answers delete-safety questions. |
| Never overwrite human decisions | Any `human_*` field survives refreshes. |
| Never guess canonical | Unknown stays `UNKNOWN` + NEED HUMAN REVIEW. |
| Never change backtest results silently | Frozen contracts + one-variable-at-a-time. |
| Never commit/push automatically | The agent prepares; the human commits. |

## Quick reference

```bash
# 1. Refresh the single source of truth
python control_center/refresh_registry.py

# 2. Open the Control Center
streamlit run control_center/control_center.py

# 3. Answer "can I delete X?" without deleting anything
#    -> Module Registry -> select X -> delete-safety panel
```
